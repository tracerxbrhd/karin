# CODEX TASK — Karin v0.4: Cassette-inspired Final UX Refinement

## 0. Контекст и цель

Продолжи разработку Karin в существующем Draft PR #15.

**Репозиторий:** `tracerxbrhd/karin`

**Ветка:** `feature/v0.4-native-music-ui`

**Исходная принятая для сравнения ревизия:** `2e3ae41a8480b8f5f437f739c02cb925af69e884`

Начни с проверки актуального HEAD и прочитай `AGENTS.md`, архитектурную документацию, ADR-0022–0024 и действующее задание v0.4.

Не создавай новый PR, не выполняй merge и не удаляй ветки.

### Новые визуальные референсы

К этому заданию владелец прикладывает два скриншота, на которых приложения расположены рядом:

- **Слева — Cassette.**
- **Справа — текущая Karin v0.4.**

Первый скриншот сравнивает понравившиеся композиции. Второй — плейлисты.

Используй изображения как основное свидетельство пользовательских замечаний, но не копируй буквально элементы, графические ресурсы или исходный код Cassette.

### Цель

Довести текущий интерфейс Karin до более цельного, зрелого и удобного состояния, сохранив все уже принятые технические решения.

**Это финальная UI/UX-полировка текущей итерации, а не очередная полная перестройка приложения.**

Приоритеты:

1. Переработать экран понравившихся треков по композиционному принципу Cassette.
2. Добавить поиск внутри понравившихся треков и каждого отдельного плейлиста.
3. Улучшить композицию Player Bar.
4. Увеличить обложки плейлистов.
5. Переименовать «Моя волна» в «Главная» и подготовить её как будущий музыкальный стартовый экран.

Всё должно оставаться нативным для GTK4/Libadwaita.

## 1. P0 — экран «Нравится»

Сейчас Karin показывает небольшой заголовок «Любимые треки», кнопку «Слушать» и список композиций.

В Cassette эта коллекция воспринимается как полноценный музыкальный плейлист с собственной визуальной идентичностью.

**Необходимо перенять именно этот композиционный принцип.**

### 1.1. Шапка понравившихся треков

Создай выразительный заголовок коллекции.

Рекомендуемая структура:

- Крупная обложка/иллюстрация понравившихся треков слева.
- Название «Мне нравится» или «Любимые треки».
- Компактная информация о количестве композиций.
- Общая длительность, если её можно достоверно вычислить по полному набору данных.
- Основная кнопка воспроизведения.
- Компактные дополнительные действия.

Для обложки используй доступную обложку коллекции либо оригинальное нативное оформление с символом сердца. Не копируй графический ресурс Cassette.

Не выводи выдуманную общую длительность, когда загружена только часть библиотеки.

### 1.2. Адаптивность заголовка

На широком экране обложка и метаданные располагаются горизонтально.

На среднем — уменьшается обложка, действия компактно группируются.

На узком — заголовок перестраивается, но не занимает большую часть высоты окна.

Главная цель — добиться выразительной композиции без гигантского пустого пространства.

### 1.3. Строки треков

Сохрани существующие компактные строки с обложкой, названием, исполнителем и длительностью.

Улучши:

- Положение контекстных действий.
- Выделение воспроизводимого трека.
- Индикацию Like.
- Hover/focus.
- Типографическую иерархию.
- Согласованность строк с обновлённой шапкой.

Не делай каждую строку тяжёлой отдельной карточкой.

По возможности приблизь плотность и удобство чтения к Cassette, сохранив собственный стиль Karin.

## 2. P0 — поиск внутри музыкальных коллекций

**Обязательно реализуй поиск по трекам в «Нравится» и во всех открываемых плейлистах.**

Это отдельная функция от глобального поиска Яндекс Музыки.

### 2.1. Где должен быть поиск

Поиск нужен:

- В «Нравится».
- В каждом собственном плейлисте.
- В каждом понравившемся плейлисте, содержимое которого доступно.
- В других экранах полных списков треков, если они используют тот же компонент коллекции и функционально совместимы.

Не нужно добавлять отдельное поле поиска на каждую карточку плейлиста в общей сетке.

**Поиск появляется внутри открытой коллекции.**

### 2.2. UI поиска

Ориентируйся на Cassette:

- Компактное поле под заголовком коллекции.
- Иконка поиска.
- Короткий placeholder, например «Поиск по трекам».
- Кнопка очистки.
- Аккуратное расположение относительно сортировки и других действий.

Поле поиска не должно доминировать над контентом.

На узких окнах разрешается компактное раскрываемое поле, если это улучшает компоновку.

### 2.3. Поведение

Поиск должен находить композиции по:

- Названию.
- Исполнителю.
- При наличии данных — альбому.

Требования:

- Регистронезависимый поиск.
- Корректная работа с кириллицей и Unicode.
- Обновление результатов при вводе.
- Отсутствие необходимости нажимать Enter для каждого запроса.
- Сохранение стабильного состояния интерфейса.
- Очистка запроса возвращает обычный список.
- Переход в другой плейлист не применяет к нему случайно старый запрос.
- Пустой результат оформляется аккуратно.

### 2.4. Совместимость с continuous loading

Это критически важно.

В v0.4 уже есть ограниченная система непрерывной подгрузки треков: максимум 2000 позиций / 100 страниц отображения и контекст воспроизведения до 500 элементов.

Поиск не должен разрушать эти ограничения.

Сначала исследуй реальные контракты MusicService.

Если подтверждён безопасный серверный поиск внутри конкретной коллекции — можно использовать его.

Если подходящего метода нет, реализуй поиск по загруженным данным с корректной постепенной обработкой следующих порций, когда это необходимо.

Не выдавай отсутствие совпадений в загруженной части за отсутствие совпадений во всей удалённой коллекции.

При необходимости показывай короткую ненавязчивую индикацию неполного охвата и возможность продолжить поиск.

Не инициируй массовую загрузку всей библиотеки на каждый введённый символ.

### 2.5. Воспроизведение из результатов

После фильтрации:

- Клик по треку запускает именно выбранное вхождение.
- Повторяющиеся Track ID обрабатываются корректно.
- Порядок воспроизведения соответствует понятной пользователю модели результатов.
- Фильтрация не меняет уже играющую очередь.
- Новое воспроизведение создаёт корректный ограниченный PlaybackContext.
- Дополнительная подгрузка не разрушает текущую очередь.

Не дублируй исходные модели треков без необходимости.

Используй единый переиспользуемый компонент поиска/фильтрации для коллекций.

### 2.6. Сортировка

На приложенном скриншоте Cassette рядом с поиском присутствует сортировка.

Оцени её целесообразность для Karin.

Если реализуешь:

- Исходный порядок.
- По названию.
- По исполнителю.
- По длительности, если известна.

Не сортируй удалённую коллекцию только по неполной странице, выдавая результат за полную глобальную сортировку.

Не изменяй существующую очередь при переключении сортировки.

Если корректная сортировка всей коллекции требует отдельного сложного API-контракта, зафиксируй ограничение вместо фиктивного поведения.

## 3. P0 — Player Bar ближе к Cassette

Текущий Player Bar уже работает, но композиционно уступает Cassette.

На приложенном скриншоте хорошо видно, что у Cassette удобнее сгруппированы транспортные действия, Like, дополнительные режимы и прогресс.

Нужно улучшить именно эргономику и визуальную композицию.

### 3.1. Сохранить уже работающее поведение

Обязательно сохранить:

- Player Bar скрыт до начала воспроизведения.
- Плавно появляется снизу.
- Не исчезает при Pause.
- Скрывается при Stop/очистке очереди/logout согласно существующей модели.
- Весь блок текущего трека открывает правую панель.
- Правая панель остаётся закреплённой.
- Очередь открывается в той же правой панели.
- Shuffle и Repeat работают по реальной модели MusicQueue.
- MPRIS синхронизирован.

Не возвращать видимую кнопку Stop.

### 3.2. Переработать композицию

Широкий экран:

**Левая часть**

- Обложка.
- Название.
- Исполнитель.
- Like с понятной активностью.

**Центральная часть**

- Shuffle.
- Previous.
- Play/Pause.
- Next.
- Repeat.

**Правая часть**

- Очередь.
- Громкость.
- Необходимые дополнительные действия.

Прогресс и время расположить согласованно с транспортным блоком, а не как отдельные плохо связанные элементы.

Центрировать транспорт независимо от длины названия трека.

### 3.3. Визуальные улучшения

- Уменьшить случайные промежутки между связанными кнопками.
- Привести symbolic icons к единому визуальному размеру.
- Увеличить удобство попадания по интерактивным областям.
- Сделать текущее состояние Shuffle/Repeat очевидным.
- Убрать визуальное ощущение, что Like существует отдельно от всех остальных элементов.
- Сохранить понятное время воспроизведения и удобный Seek.
- Не делать Player Bar излишне высоким.

Для Like предпочтительно использовать узнаваемую иконку сердца в духе музыкальных приложений, если это согласуется с нативным icon theme. Оценить миграцию от текущей звезды без изменения серверной семантики.

Like должен оставаться подтверждаемым сервером.

**Dislike не выводить как рабочее действие, пока его реальный API-контракт не подтверждён.**

### 3.4. Адаптивный Player Bar

На компактных окнах второстепенные элементы могут перемещаться в overflow/popover.

Но нельзя скрывать весь основной транспорт или делать управление непредсказуемым.

Не создавай разные независимые плееры для wide и compact.

Используй одну прикладную модель и согласованное представление.

### 3.5. Анимация

Сохрани SlideUp.

Проверь первое появление после холодного запуска, поскольку предыдущая облачная приёмка зафиксировала разрыв кадров около 117 мс.

Не маскируй проблему увеличением длительности анимации или искусственным ожиданием.

Если обнаружена воспроизводимая причина, исправь её. Если нет — оставь точные наблюдения и обозначь пользовательскую Fedora-проверку как pending.

## 4. P1 — обложки плейлистов

Текущий раздел «Плейлисты» в целом устраивает владельца.

Ему требуется преимущественно визуальная полировка, а не перестройка функциональности.

### Изменения

- Увеличить размеры обложек.
- Сделать сетку более выразительной.
- Уточнить отступы.
- Сохранить аккуратные названия и количество композиций.
- Не растягивать один плейлист на всю ширину.
- Сохранить отдельные секции собственных и понравившихся плейлистов.
- Плитка создания плейлиста должна визуально соответствовать остальной сетке.

Ориентир:

- Широкое окно: обложки около 180–210 logical px.
- Среднее: около 145–175 px.
- Компактное: размер определяется доступной шириной, без горизонтального переполнения.

Это ориентиры, а не обязательные постоянные значения.

Подбирай размеры по реальному GTK layout.

Сохрани:

- Настоящие обложки.
- Server-confirmed playlist creation.
- Корректное открытие плейлистов.
- Loading/empty/error states.
- Клавиатурную навигацию.
- HiDPI.

## 5. P1 — «Моя волна» становится «Главная»

Переименуй первичную вкладку **«Моя волна» → «Главная»**.

Но речь не только о смене текста.

### Новое назначение

Главная — будущий музыкальный стартовый экран Karin.

В дальнейшем здесь будут располагаться:

- Моя волна.
- Персональные музыкальные рекомендации.
- Подборки.
- Доступные музыкальные активности и быстрый возврат к прослушиванию.

Однако сейчас необходимо использовать только реально подтверждённые возможности.

### Что реализовать сейчас

Создай аккуратный базовый экран главной.

Он может содержать:

- Компактный блок «Моя волна» с честным статусом недоступности.
- Реальные пользовательские плейлисты.
- Доступные любимые композиции.
- Быстрые переходы к уже существующим разделам.

Не обязательно выводить сразу всё. Выбери композицию, которая лучше использует пространство и не дублирует соседние вкладки.

**Главная не должна быть огромной пустой заглушкой.**

Но и не должна создавать впечатление, что неподтверждённые рекомендации уже работают.

### Архитектура

Предусмотри возможность будущих музыкальных секций без необходимости заново переписывать навигацию.

При этом не создавай сложную систему виджетных плагинов или абстрактный конструктор экранов заранее.

Реализация реальной «Моей волны» и рекомендательного API остаётся отдельной задачей.

## 6. Общие требования к визуальному качеству

Главный ориентир — Cassette-like простота, но без буквального копирования.

Интерфейс должен:

- Быть визуально лёгким.
- Иметь понятную иерархию.
- Уважать пользовательское пространство.
- Использовать обложки как значимые элементы.
- Не содержать лишних абзацев.
- Не перегружаться декоративными контейнерами.
- Оставаться нативным GTK4/Libadwaita.

Минимализм не должен ухудшать доступность.

Технические состояния, ошибки и подтверждения сохраняют необходимые сообщения.

Не использовать чужие иконки/обложки из Cassette в релизной сборке без соответствующих прав.

## 7. Архитектурные ограничения

Не переписывай без технической необходимости:

- Auth / Persistent Session.
- MusicService.
- StreamResolver.
- GStreamer Audio Engine.
- PlaybackController.
- MusicQueue и Shuffle/Repeat.
- MPRIS 2.2.
- Cache.
- Flatpak.
- Server-confirmed playlist creation.
- Ограниченную continuous-loading модель.

Новый поиск внутри коллекции должен оставаться частью прикладного/UI-слоя, не заставляя GTK напрямую работать с неофициальными HTTP-ответами.

Сохраняй корректные поколения запросов, cancellation и account isolation.

Не добавляй новые постоянные службы, веб-движок для UI или тяжёлые зависимости без необходимости.

Если субагенты недоступны, выполни те же направления последовательно.

## 9. Визуальная проверка

После реализации создай новые реальные GTK-скриншоты.

Обязательно покажи:

1. «Нравится» с новой шапкой.
2. «Нравится» с активным поиском.
3. Плейлист с поиском.
4. Плейлисты с увеличенными обложками.
5. Главную.
6. Новый широкий Player Bar.
7. Новый компактный Player Bar.
8. Скрытый плеер до первого Play.
9. Правую панель Track Info и Queue.
10. Светлую и тёмную темы.

Размеры для приёмки:

- 420×720.
- 850×750 — приблизительно для сравнения с приложенными скриншотами.
- 900×650.

## 10. Функциональные критерии приёмки

### Liked

- Есть полноценная шапка с обложкой.
- Поиск внутри коллекции работает.
- Фильтрация не ломает очередь.
- Like/Unlike работает с подтверждением.
- Загрузка больших коллекций остаётся ограниченной.
- Пустой и частично загруженный список отображаются честно.

### Playlists

- Обложки заметно крупнее.
- Поиск работает внутри каждого плейлиста.
- Создание и открытие плейлистов не регрессировали.
- Поиск сохраняет корректность при загрузке следующих страниц.
- Нет сброса воспроизведения от фильтрации.

### Player Bar

- Визуальная композиция заметно ближе к утверждённому референсу.
- Playback controls, Seek, Volume, Like, Shuffle и Repeat доступны и корректны.
- Нет видимой Stop.
- Полный блок трека открывает Info.
- Очередь открывается в правой панели.
- Плавное появление и скрытие сохранены.
- Компактная компоновка не переполняется.

### Главная

- Первая вкладка называется «Главная».
- Внутри есть место для будущей «Моей волны».
- Нет фальшивых рекомендаций.
- Не осталось огромной пустой заглушки как единственного содержимого.
